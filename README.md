# CS-230-Final
Summary:

This CS 230 project focused on designing The Gaming Room’s “Draw It or Lose It” application for multiple operating platforms. The project demonstrates software design, object-oriented programming, system architecture, platform evaluation, and translating client requirements into a scalable software solution.

Reflection:

The Gaming Room was the client for this project. They wanted to expand their existing game, Draw It or Lose It, so that it could run on multiple operating platforms instead of being limited to one environment. The software needed to support multiple teams and players while making sure that game, team, and player names remained unique. The goal was to design the application in a way that was organized, scalable, and able to work across different platforms.

One thing I think I did particularly well was breaking down the client's requirements and connecting them to the technical design of the application. I was able to compare different operating platforms and consider their strengths and weaknesses before making a recommendation. I also think the design document helped me organize the different parts of the application before focusing on the actual code.

Working through the design document was helpful because it made me think about the structure of the software before implementing it. Instead of immediately writing code, I had to consider how the classes would interact, how data would be managed, and what requirements needed to be met. This made the development process more organized and helped me understand why planning is an important part of software development.

If I could revise one part of my work, I would improve some of the technical explanations in the design document. I would add more detail about why certain technologies and platforms were chosen instead of only describing their advantages and disadvantages. I think this would make the document more useful to both the client and the development team because the reasoning behind each recommendation would be clearer.

I interpreted the user's needs by focusing on what The Gaming Room wanted the application to accomplish and then considering how those requirements could be implemented in the software design. It is important to consider the user's needs because software can technically work correctly but still fail if it does not solve the problem the user actually has. Keeping the client's requirements in mind helps make sure the final product is useful, reliable, and easier for the user to work with.

My approach to designing the software was to first understand the requirements, break the application into smaller parts, and then determine how those parts should work together. I also compared the available operating platforms before deciding which environment would work best for the application. In future projects, I would continue using design documents, diagrams, requirement analysis, and platform comparisons before beginning development. I would also try to get feedback earlier in the process so changes can be made before too much of the application has already been developed.
